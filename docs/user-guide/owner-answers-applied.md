# إجابات صاحب الشركة — ما نُفِّذ

ثمانية أسئلة أُرسلت في «قراءة في مسارات العمل»، وهذه إجاباتها وما ترتّب
عليها. ستّةٌ منها إعدادٌ في بناء المسار، **واثنتان استلزمتا بناءً في النظام**.

> **لم تُستورَد مسارات الشركة الـ ٤٣** — كما طُلب. وبُني بدلها **مسار واحد
> شامل** يُظهر كل ما صار النظام يقدر عليه. تفصيله في §٣.

## ٢. البناءان الجديدان

### أ) المراقب — يرى ولا يُكلَّف

كان المشارك يُكلَّف عملًا **لِيرى**. فمن أردنا له الاطّلاع وحده كنّا نضطرّ إلى
تكليفه، فتصله مهمّة لا عمل فيها، وتقف المرحلة عنده تحت سياسة «الكل».

صار للمشارك خانة **«مراقب — يرى ولا يُكلَّف»**:

- يرى **المعاملة كلها** من أوّلها إلى آخرها، لا مرحلته وحدها
- **لا تُنشأ له مهمّة** ولا تظهر في صندوق وارده
- **لا يمنع إغلاق** أيّ مرحلة
- يُوضَع دورًا أو شخصًا — «المدير العام» أو «المراجعة الداخلية»

> ولأن مرحلةً كلُّ من فيها مراقب تقف بلا صاحب، صار **فحص المسار** يرفضها قبل
> النشر ويقول: «مرحلة بمراقبين فقط — لا أحد يُكلَّف بها فتقف المعاملة».

### ب) الموعد النهائيّ في التقويم

«مسار ١ السبت ١٢ · مسار ٢ الثلاثاء ١٢» ليست مدّة، بل موعدٌ ثابت. والفرق
جوهريّ:

|            | يبدأ من              | مثال                 |
| ---------- | -------------------- | -------------------- |
| **المدّة** | لحظة وصول المعاملة   | «أمامك ٤ ساعات»      |
| **الموعد** | التقويم، لا المعاملة | «قبل الثلاثاء ظهرًا» |

ولا يُغني أحدهما عن الآخر، فصارا معًا على المرحلة. في لوحة المرحلة:

- **أيام الأسبوع** — تُختار بالضغط، وأكثر من يوم مسموح
- **الساعة**
- **عند التجاوز**: `تنبيه المكلَّف` أو `تنبيه المكلَّف والإدارة`

والموعد **يُحسب لحظة بدء المرحلة ويُثبَّت**. فلو عدّلت الشركة الموعد غدًا، لا
تنقلب مواعيد معاملاتٍ جارية تحت أصحابها. ومرحلة الالتقاء التي تُنشأ معلَّقة
وتبدأ بعد يوم يُحسب موعدها **من يوم بدئها** لا من إنشاء صفّها.

ويمرّ مشغّل كل خمس دقائق فينبّه **مرّة واحدة** على ما تجاوز.

## ٣. المسار الشامل

`subcontractor_claim` · **«مستخلص مقاول باطن — نموذج شامل»** · منشور ونشِط ·
٦ مراحل · ١٠ أزرار · ٩ وجهات.

بُني ليُظهر **كل** ما في المحرّك في مسار واحد، لا ليكون مسار عمل حقيقيًّا.

| #   | المرحلة          | ما تُظهره                                 | المشاركون                                             | المدّة |
| --- | ---------------- | ----------------------------------------- | ----------------------------------------------------- | ------ |
| ١   | إعداد المستخلص   | بداية · **مراقب**                         | طالب المعاملة · **مراقب: موظف عادي**                  | ٤٨٠    |
| ٢   | المراجعة الفنية  | سياسة **الكل** · **مشارك اختياري**        | مشروعيّ: مهندس · مشروعيّ: مدير مشروع _(اختياري)_      | ٢٤٠    |
| ٣   | الحسابات         | **موعد تقويميّ** · **تصعيد**              | شركة: مدير البرنامج                                   | ٣٠٠    |
| ٤   | اعتماد الإدارة   | **أوّلهم** · **حجز حصريّ** · **شرط مرفق** | مشروعيّ: مدير مشروع **(موقّع)** · شركة: مدير البرنامج | ٢٤٠    |
| ٥   | التدقيق النهائي  | **التقاء** · **يلزم الاستلام**            | شركة: مدير البرنامج                                   | ١٨٠    |
| ٦   | الإغلاق والأرشفة | نهاية · **أرشيف**                         | شركة: مدير النظام                                     | ٤٨٠    |

### الأزرار — الأنواع الخمسة

| المرحلة         | الزرّ           | النوع                                     |
| --------------- | --------------- | ----------------------------------------- |
| الإعداد         | إرسال للمراجعة  | انتقال                                    |
| المراجعة الفنية | اعتماد فني      | انتقال                                    |
| المراجعة الفنية | **رفض / إرجاع** | **إرجاع** · بسبب إلزاميّ · مهلة جديدة ١٢٠ |

| اعتماد الإدارة  | اعتماد          | انتقال                                    |

### التفريع

«إرسال للمراجعة» له **ثلاث** وجهات:

| الأولوية | الشرط              | الوجهة          |
| -------- | ------------------ | --------------- |
| ١        | المعاملة على مشروع | المراجعة الفنية |
| ١        | المعاملة على مشروع | الحسابات        |
| ٩        | بلا شرط            | المراجعة الفنية |

**الأولوية نفسها ⇒ الفرعان يُفتحان معًا**، ويلتقيان عند التدقيق النهائي الذي
لا يبدأ قبل أن يهدأ كلاهما.

## ٤. مقيس لا موصوف

أُنشئ مشروع ومعاملة، وقِيس ما يراه كل حساب، ثم أُلغي كل شيء:

| الحساب            | يرى المعاملة | له مهمّة | السبب                                |
| ----------------- | ------------ | -------- | ------------------------------------ |
| `admin`           | ✅           | ✗        | يقرأ كل المعاملات                    |
| `program.manager` | ✅           | ✗        | يقرأ كل المعاملات                    |
| `engineer`        | ✅           | ✅       | هو طالب المعاملة                     |
| **`employee`**    | **✅**       | **✗**    | **مراقب — وهذا هو الجديد**           |
| `project.manager` | ✗            | ✗        | مرحلته لم تُفتح بعدُ فليس طرفًا      |
| `hr.manager`      | ✗            | ✗        | لا يملك صلاحية قراءة المعاملات أصلًا |

و`employee` كان يرى **صفرًا** قبل خانة المراقب — ولم يتغيّر له دورٌ ولا
صلاحية، بل خانةٌ واحدة في بناء المسار.

### والموعد قِيس كذلك

فُتحت «الحسابات» يوم الثلاثاء بعد الظهر، فحُسب موعدها:

```
{"time":"12:00","days":[6,2]}   →   السبت ١٢/٠٩ الساعة ١٢:٠٠
```

أي أقرب موعدٍ بعد دخولها المرحلة — لا الثلاثاء الذي مضت ظهيرته.

## ٥. كيف تُعيد بناءه

المسار موجود في القاعدة. ولإعادته من الصفر ادخل بـ `admin@example.com`
(كلمة المرور `Demo@2026!`) ← **مسارات سير العمل** ← **إضافة مسار**، ثم ابنِ
الجدول أعلاه. أو احذفه من الشاشة — يُحذف ما دامت لم تسر عليه معاملة، وإن
سارت قال لك **كم معاملة ولماذا رُفض الحذف**.
